Visão Geral

Construir um WebApp real com processo profissional

O template organiza a jornada inteira: máquina, contas, escopo, banco, branches, homologação e produção.

🎯 Resultado esperado

  • Ambientes isolados para HML e PROD
  • Versionamento correto com main e develop
  • Deploy profissional, seguro e rastreável

🛡️ Regra principal

  • Cada projeto é 100% independente
  • Cada ambiente tem seu banco separado
  • Produção é consequência do processo

1. Local & Ideação
Antigravity + MCP
➔
2. Branch develop
Supabase HML + Vercel Preview
➔
3. Branch main
Supabase PROD + Vercel Production
Fase 1

Preparação do Ambiente & Isolamento Total

Etapa 01

Pré-requisitos no Windows do zero

A preparação do ambiente vem antes do código para evitar falhas de permissão, certificados e ferramentas incompletas.

1. Atualizar o Windows

  • Executar o Windows Update e aplicar todas as atualizações recomendadas
  • Reiniciar o computador após a conclusão
Isso ajuda a reduzir drasticamente riscos de erros de permissão e certificados no terminal.

2. Instalar navegador moderno

Escolha um navegador principal para gerenciar os painéis do projeto:

Chrome Edge Firefox Opera

3. Criar contas do projeto

Crie uma conta de serviço no Proton Mail para o projeto e acesse as plataformas necessárias:

Proton Mail GitHub Supabase Vercel Claude Google AI Studio

⚙️ Ferramentas Base

  • Git com instalação padrão
  • GitHub CLI (`gh`) para autenticação no terminal
  • Node.js LTS (não escolha a opção do Chocolatey)
  • Windows Terminal recomendado

💻 Ferramentas de Trabalho

  • Antigravity IDE como ambiente principal
  • Docker Desktop com suporte a WSL 2
  • Reinicie o computador após a instalação do Docker
💡 Dica: Anote suas credenciais em um lugar seguro e de fácil acesso (ex: Notepad ou Notion) para acelerar a rotina.
Verificação de Instalação no Terminal bash 
git --version
gh --version
node -v
npm -v
docker --version
Etapa 02

Isolamento total do projeto

Antes de escrever telas ou código, o processo exige isolamento de identidade e banco de dados.

📧 E-mail Exclusivo

Utilize um provedor como o Proton Mail:

todoapp.dev@proton.me
  • Garante separação entre diferentes projetos
  • Facilita transferência ou acesso de equipe
  • Eleva o padrão de segurança da operação

🗄️ Dois Projetos no Supabase

Crie dois projetos independentes no Dashboard:

  • Supabase Homologação (HML)
  • Supabase Produção (PROD)
  • ⚠️ Nunca compartilhe a mesma instância entre ambientes
⚠️ Regra de Segurança: Homologação e Produção devem possuir chaves de API, credenciais e bancos totalmente isolados.
Fase 2

UX, Design System & Ideação com IA

Etapa 03

Prototipação visual e design system

Busque referências visuais, extraia paleta de cores e valide os fluxos antes do backend.

  1. Buscar referências visuais em plataformas como Dribbble, Pinterest, Awwwards e 21st.dev.
  2. Definir paleta de cores, hierarquia tipográfica, espaçamento e componentes reutilizáveis
  3. Criar o protótipo funcional no Google AI Studio (Opcional)
  4. Validar visualmente a experiência do usuário (UX) sem necessidade de backend ou deploy prévio
✨ Ordem Recomendada: Primeiro a UX e o Design System, depois o código. Essa prática economiza horas de refatoração.
Etapa 04

Ideação com IA sem escrever código

Defina o escopo funcional, regras de negócio, estrutura de telas e arquitetura de dados.

Ferramenta sugerida: Claude.

💡 Para comparar modelos de IA e desempenho em código, consulte o LM Arena Leaderboard e o Artificial Analysis.
Prompt de Especificação Inicial prompt 
Crie a especificação de um webapp simples de To Do List.
Inclua:
- Funcionalidades principais
- Estrutura de telas
- Regras de negócio
- Estrutura inicial de banco de dados
Infraestrutura:
- Supabase: Banco de Dados, Storage e Autenticação

Crie um PRD.md com todo o prompt
🎙️ Aceleração por voz (Bônus): Experimente ferramentas de digitação por voz como Wispr Flow, Amical ou Handy para ditar seus prompts.

📁 Próximo Passo no Windows Explorer

Crie uma pasta com o nome do projeto no seu computador e salve dentro dela o arquivo PRD.md gerado pela IA.

Etapa 05

Especificação do WebApp de Exemplo

O modelo utiliza um To-Do App para exemplificar regras de banco, autenticação e segurança.

⚡ Funcionalidades

  • Autenticação: Login, cadastro, logout e esqueci a senha
  • CRUD de tarefas com prioridade, prazo e anexos
  • Filtros dinâmicos por status, prioridade e categoria
  • Busca por título e descrição

📱 Telas

  • Tela de Autenticação (Login / Cadastro)
  • Dashboard Principal com estatísticas
  • Modal de Criação / Edição de tarefa
  • Gerenciamento de categorias e anexos

📋 Regras de Negócio

  • Título da tarefa obrigatório (máx 120 caracteres)
  • Senha de usuário com no mínimo 6 caracteres
  • Validação de datas de vencimento
  • Categorias padrão geradas no primeiro acesso

🔒 Segurança e RLS

  • RLS (Row Level Security) em profiles, categories e tasks
  • Bucket de Storage privado para anexos
  • Policies por usuário em banco e storage
  • Gerenciamento de sessão pelo Supabase Auth
Fase 3

Antigravity, Versionamento & Supabase CLI

Etapa 06

Desenvolvimento no Antigravity e uso do MCP

Conecte a IDE Antigravity ao Supabase de Homologação usando o Model Context Protocol (MCP).

🤖 Antigravity IDE

  • Abra o projeto no Antigravity
  • Utilize o assistente de código como centro do seu workflow

🔌 MCP do Supabase

  • Conecte o MCP exclusivamente ao projeto de Homologação
  • Sincronize o contexto global de ferramentas
⚠️ Atenção aos limites do Supabase Free:
  • Banco de dados: até 500 MB
  • Auth: até 50.000 usuários ativos por mês (MAU)
  • Storage: até 1 GB
  • Inatividade: Projetos sem atividade por 7 dias podem ser pausados
Documentação MCP Supabase Supabase Auth Guide
Etapa 07

Código base e versionamento correto

Configure o Git com uma estrutura clara de branches para separação de ambientes.

Inicialização do Repositório Git bash 
git init
git branch -M main
git remote add origin https://github.com/SEU_USUARIO/SEU_REPO.git
git add .
git commit -m "chore: initial project structure"
git push -u origin main
Criar Branch de Homologação bash 
git checkout -b develop
git push -u origin develop

git config user.name "Seu Nome"
git config user.email "seu-email-do-projeto@proton.me"
🌿 Convenção de Branches:
• main ➔ Produção (Versão estável e pública)
• develop ➔ Homologação (Ambiente de desenvolvimento e testes)
Etapa 08

Configuração correta do Supabase CLI

O CLI deve ser inicializado dentro do projeto local via npx, sem instalação global.

Comandos do Supabase CLI bash 
npx supabase init
npx supabase login
npx supabase link --project-ref SEU_PROJECT_REF_HML
💡 Regra de Ouro: Se o comando começa com npx, ele pertence ao pacote do projeto e garante consistência entre membros da equipe.
Etapa 09

Banco de dados, migrations e variáveis

Crie alterações de esquema via migrations SQL versionadas e configure as variáveis de ambiente.

Gerar e Aplicar Migration bash 
npx supabase db diff -f create_tasks_table
git add supabase/migrations
git commit -m "chore(db): create tasks table"
npx supabase db push

⚙️ Supabase Setup

  1. Criar projetos no Supabase
  2. Executar migrations SQL
  3. Configurar Storage Buckets
  4. Habilitar Email Auth
  5. Copiar URL e Anon Key

🔄 Fluxo de Dados

  1. Usuário realiza login
  2. Auth valida credenciais
  3. RLS filtra dados por user_id
  4. Storage recebe anexos autorizados
Variáveis de Ambiente (.env.local) env 
NEXT_PUBLIC_SUPABASE_URL=https://your-project-url.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key
SUPABASE_SERVICE_ROLE_KEY=your-service-role-key
Etapa 10

Stack tecnológica e estrutura do projeto

Organização recomendada para um WebApp moderno, rápido e escalável.

🎨 Frontend Stack

  • Next.js 14+ com App Router
  • TypeScript para segurança de tipos
  • Tailwind CSS para estilização
  • shadcn/ui ou Radix UI para componentes
  • React Hook Form + Zod para formulários

⚡ Backend & Deploy Stack

  • Supabase (PostgreSQL, Auth, Storage)
  • @supabase/supabase-js
  • Vercel com CI/CD automático via Git
  • Variáveis de ambiente seguras

├── src/

│   ├── components/
│   ├── lib/

Fase 4

CI/CD, Deploy em Produção & Monitoramento

Etapa 11

Homologação com CI/CD e Pull Request

Valide as alterações em um ambiente de preview isolado antes de enviar para produção.

Commit e Push na branch develop bash 
git add .
git commit -m "feat: todo list funcional"
git push origin develop
🚀 O push na branch develop faz a Vercel gerar automaticamente uma URL de Preview Deployment para testes em homologação.
Documentação Vercel Previews
Fluxo de Pull Request flow 
develop ➔ main (Revisão e Merge)
Etapa 12

Produção e validação pós-deploy

Após aprovação em homologação, execute o merge controlado para a branch principal.

Merge na main e Migrations em Produção bash 
git checkout main
git merge develop
git push origin main

npx supabase link --project-ref SEU_PROJECT_REF_PROD
npx supabase db push

✅ Check-list de Validação em Produção

  • Testar criação de conta e login de usuário
  • Testar inclusão, edição e exclusão de itens
  • Verificar upload e visualização de anexos
  • Validar logout e expiração de sessão
Etapa 13

Rollback e monitoramento contínuo

Estratégia para resposta rápida a incidentes e monitoração de disponibilidade.

↺ Rollback

  • Frontend: Reverter versão instantaneamente no dashboard da Vercel
  • Banco: Aplicar correção via nova migration SQL reversa

📊 Monitoramento

  • Acompanhar uptime da aplicação em produção
  • Monitorar endpoints da API do Supabase
  • Receber alertas via Telegram, Discord ou E-mail
Executar Uptime Kuma via Docker bash 
docker run -d --restart=always -p 3001:3001 \
  -v uptime-kuma:/app/data \
  --name uptime-kuma \
  louislam/uptime-kuma:1

Etapa 14

Os princípios que não podem ser quebrados

Pilares fundamentais para manter a saúde e integridade do seu projeto.

❌ NUNCA

  • Desenvolver código diretamente na branch main
  • Conectar o MCP ou IDE ao Supabase de Produção
  • Subir credenciais secretas para repositórios públicos

✅ SEMPRE

  • Manter o MCP apontado para o Supabase de Homologação
  • Validar alterações no Vercel Preview antes do merge
  • Tratar produção como consequência do processo
"Produção não é lugar para experimentar. O ambiente para errar rápido e barato é a ideação e a homologação."
